Written 2026-09-25 on branch `refork/linux` (based on LizardByte/Sunshine `upstream/master` @
`05350c05`, 2026-09-24). Fork audited: `linux-support` @ `c21aae37` (2026-09-25).
Fork point (merge base) with upstream: `34054a20`, 2024-08-26.

Goal this document serves: **the Linux surface of this fork equals LizardByte's, with Biaogo's
virtual-display work re-applied on top.** It answers "what differs", states why the goal cannot be
reached by editing files in place, picks the lane, and lists exactly what has to be re-applied.

## 2. The premise "AlkaidLab is Windows-only, they never touched Linux" is false — but narrowly

Commits touching the Linux-path set in the fork lineage (`34054a20..linux-support`), by author:

| author | commits on Linux paths |
|---|---|
| qiin2333 (+ `qiin` 4 + `Qian23333` 2) | 125 |
| Biaogo | 43 (+7 in the later batch-port series) |
| Yundi339 | 30 |
| upstream authors imported via cherry-picks (Cameron Gutman, ShadowLemoon, ReenigneArcher, …) | 17 |

What those AlkaidLab commits actually are, per file:

- `src/platform/common.h` (43) — shared header; HDR/RTX-HDR, DualSense, RTX SDK, mic plumbing … —
  Windows features whose declarations live in a cross-platform header.
- `src/platform/linux/misc.cpp` (8) — upstream cherry-picks (`f46b4b11`), sleep-mode options
  (#511), boost 1.89 bump (#430), tray/log fixes (#173, #359).
- `src/platform/linux/audio.cpp` (4) — **genuinely Linux**: multi-client microphone mixing
  (`d80144e7`, #929, adds `src/mic_mixer.*`) and 7.1.4/12-channel surround (`d855af34`, #510).
- `src/platform/linux/display_device.cpp` (3 of 14) — incidental fixes inside a file Biaogo owns.
- `src/display_device/**`, `src/nvhttp/**`, `src/nvenc/**` — AlkaidLab's Windows VDD layer and the
  nvhttp module split; the Linux build only needs stubs for them (see the fork's own commits
  `45017b7b`, `61382c26`, `4e9305d6`).

So AlkaidLab did not develop Linux features; they reshaped the *shared* tree such that Linux now
needs stubs to build, and added two Linux-relevant audio features. Both facts matter for the plan
below: the shared-tree reshape is exactly what blocks a local "make Linux match upstream" edit.

## 3. Why the Linux files cannot simply be swapped in place

Upstream's Linux translation units compile against upstream's core: the `platf::` interface in
`src/platform/common.h`, the 2026 capture/encode pipeline in `src/video.cpp` / `src/stream.cpp` /
`src/rtsp.cpp`, the single-file `src/nvhttp.cpp`, `lizardbyte::common::get_env`, and the
`libdisplaydevice` / `libvirtualhid` submodules. This fork's core is AlkaidLab-shaped (`src/nvhttp`
split into 25 modules, `display_device` replaced wholesale, `common.h` carrying 459 added lines).
Dropping upstream's `kmsgrab.cpp`/`portalgrab.cpp`/`pipewire.cpp` into it does not compile, and
each fix pulls in the next upstream API — the same wall the previous sync attempts hit:

- full merge probe (2026-09-25, round 2 on this baseline): 213 conflicts → 36 files / 534 hunks /
  ~19k conflicting feature lines left after the mechanical bands, all in the shared core
  (`video.cpp` 71 hunks, `pipewire.cpp` 54, `rtsp.cpp`/`stream.cpp` 41 each, `confighttp.cpp` 32,
  `nvhttp.cpp` 31, `platform/common.h` 29, `config.cpp` 28). Merging cannot make the Linux files
  byte-identical either — it only transplants individual upstream changes into fork-shaped code.
- hand-porting single upstream Linux fixes (`sync/upstream-linux-batch`, 7 commits recovered —
  see §6): of 77 candidate Linux-path commits only 14 apply even with `git apply -3`, and the
  audit had to file many items as "pending: needs the wayland.cpp / pipewire.cpp forward-port".

Conclusion: **"Linux == upstream" implies "the core follows upstream"**, i.e. an upstream-based
tree. That is this branch.

## 4. Lane decision: re-fork onto upstream, re-apply the fork's patch series

| Lane | Linux == upstream? | Cost | Verdict |
|---|---|---|---|
| A. **Re-fork** (`refork/linux` off `upstream/master`, re-apply Biaogo's series) | yes, by construction | harness once + ~29 port items | **chosen** |
| B. Continue the full merge into `linux-support` | no (fork-shaped core stays) | 36 files / 534 hunks / ~19k lines, then still not identical | rejected for this goal |
| C. Keep hand-porting upstream Linux fixes | no | unbounded; most items blocked on file-shape forward-ports | rejected |

Why A is also the cheaper lane long-term: after the move, *this fork's own Linux surface is a
bounded patch series on top of upstream*, so every future upstream release is a rebase of that
series instead of another 534-hunk merge. The root cause of the divergence (a hard fork that never
merged upstream back, since 2024-08-26) stops compounding.

Costs and risks accepted with lane A:

1. **Build harness — PROVEN 2026-09-25** (`packaging/nix/upstream-build.nix` on this branch; model:
   nixpkgs' `pkgs/by-name/su/sunshine/package.nix`). A full cmake configuration of the
   upstream-shaped 2026-09 tree with nixpkgs dependencies succeeds — verified:
   `-- Boost libraries: Boost::filesystem;Boost::log;Boost::program_options;Boost::locale`,
   `-- Found Wayland`, `-- Found libdrm/libcap/libevdev/libva/Opus/libcurl/miniupnpnc`,
   `-- Glad Library 'glad_egl'`/`'glad_gl'`, `-- Generating done`. The pieces that mattered:
   - **Boost**: upstream's `cmake/dependencies/Boost_Sunshine.cmake` tries
     `find_package(Boost 1.89 CONFIG ...)` first. nixpkgs' boost ships the CMake config in its
     **`dev` output** (`lib/cmake/Boost-1.89.0/BoostConfig.cmake`), so `boost.dev` must be in
     `buildInputs` and `BOOST_USE_STATIC=OFF` (nixpkgs boost has no static libs) — no CPM/network
     fallback is ever reached.
   - **ffmpeg**: upstream downloads `Linux-x86_64-ffmpeg.tar.gz` from `LizardByte/build-deps` at the
     tag matching the pinned `third-party/build-deps` submodule. Fetched as a fixed-output
     derivation and passed via `FFMPEG_PREPARED_BINARIES`:
     tag `v2026.910.121303`, `sha256-1S57XfkJa+qEYQLmifWyT9ul0SASFhSk1lkk2timnOY=`
     (unpacked layout `include/` + `lib/{libavcodec,libavutil,libcbs,libhdr10plus}.a`).
   - **Vulkan headers** must come from the system: `SUNSHINE_SYSTEM_VULKAN_HEADERS=ON` + nixpkgs
     `vulkan-headers` (otherwise `cmake/compile_definitions/linux.cmake` requires them inside the
     build-deps submodule).
   - `third-party/moonlight-common-c` needs its **nested** submodules too
     (`git submodule update --init --recursive third-party/moonlight-common-c` — `enet`, `nanors`);
     a top-level `--init` only leaves `enet/` without a `CMakeLists.txt` and configure dies at
     `cmake/dependencies/common.cmake:14`.
   - everything else follows nixpkgs' package: npm substitution in `cmake/targets/common.cmake`,
     systemd/udev `find_package` removal, `GLAD_SKIP_PIP_INSTALL=ON` + python3 with jinja2/setuptools,
     `shaderc` (glslc), `wayland-scanner`, the ffmpeg `autoPatchelfHook`, the `SUNSHINE_ENABLE_*`
     matrix incl. `SUNSHINE_ENABLE_PORTAL`/`KWIN`/`VULKAN`, the UDEV/SYSTEMD install dirs, and the
     publisher/`SUNSHINE_EXECUTABLE_PATH` features.
   - `libdisplaydevice` warns `Linux is not supported yet` at configure time — expected, it is the
     Windows display-config layer; the Linux capture path does not use it.
   - **CPU variant: FULL BUILD VERIFIED** — configure + compile + link + install all pass
     (`buildPhase completed in 55 seconds` on 20 cores), binary
     `/nix/store/x2h79xg0p5kxwyd5rahqj967hxs9agr6-sunshine-refork-probe-2026.09.25/bin/sunshine`
     reports `Sunshine version: 2026.09.25 commit: refork01`, `ldd` resolves everything
     (`0 not found`). Translation units compiled include the whole upstream Linux surface:
     `portalgrab.cpp`, `kwingrab.cpp`, `kmsgrab.cpp`, `pipewire.cpp`, `wayland.cpp`, `wlgrab.cpp`,
     `vaapi.cpp`, `vulkan_encode.cpp`, `graphics.cpp`, `publish.cpp`, `audio.cpp`, `misc.cpp` and
     `src/platform/virtualhid_input.cpp` (libvirtualhid).
   - install needs `assets/web` (the npm-built UI): the harness stages a stub because the real UI
     build belongs in the packaging repo (`buildNpmPackage`); everything else installs cleanly
     (`assets/*`, `lib/systemd/user`, udev rules).
   - `third-party/build-deps`' nested FFmpeg sources, `dockle`, `nvapi`, `tray` and the nested
     `doxyconfig`/`googletest` copies stay un-checked-out on purpose — none are read on this path
     (the ffmpeg FOD replaces build-deps, docs/tests are off, tray is off, the rest is Windows/CI).
   - still to do: the CUDA variant (`--arg cudaSupport true`) and the deployment path
     (real web UI + tag/pin handoff to `foundation-sunshine-linux.nix`).
2. **AlkaidLab's Windows product surface is not carried over** to this branch (it does not build
   on Linux anyway). If a Windows build of the fork is ever needed again, it stays on
   `linux-support`/`master`.
3. **Two Linux-relevant AlkaidLab features are not in upstream** and would be dropped unless
   re-applied by choice: multi-client microphone mixing (`src/mic_mixer.*`, #929) and 7.1.4
   12-channel surround (#510). Upstream has single-client microphone capture.
4. `linux-support` keeps shipping (pin: `v2026.09.10-linux`, `e4dbcca1`) until the re-fork branch
   passes §7.

## 5. Port queue — what has to be re-applied on the upstream base

Full table: [`fork-linux-port-queue.md`](fork-linux-port-queue.md), generated by
`scripts/gen-fork-linux-port-queue.sh` from the 50 Biaogo commits that touch the Linux surface:
**29 re-apply / 18 drop / 3 assess**.

Grouped:

- **re-apply — capabilities** (must survive): client-selectable display list incl. virtual ids
  (`4773c127`, `b4640528`, `60cf3d8b`, `855821dd`), display enumeration + `/displays` endpoint for
  client validation (`386c450e`, `ec08581f`, adapt to upstream's `display_device` API),
  display-intent resolution/translation (`5a0f2720`, `a3e9ee74`, `049a3953` — needs a redesign on
  upstream's API, upstream has no intent concept), virtual-id translation + pre-flight validation
  exemptions (`bbac656c`, `c979423d`, `fdf1cb4d`, `98b5dfa2`, `f686ee05`), prep-hook session env
  plumbing (`8a4dd818`, `fa203bd3`, `04e7a1e0`, `1215ec00`), hook-created output wait and ordering
  (`9d9666fa`, `dc103e15`, `c309f758`), host-config (默认) pick must trigger the hook (`b15755b8`).
- **re-apply — the capability/permission traps that also exist in upstream itself**:
  kwin-before-kms probe order (`9a259d66`; upstream `verify_sources()` tries kms first),
  EFFECTIVE-only cap probe for the kwin display list (`33051b67`; upstream's
  `kwin_display_names()` returns a dummy `[""]` while `has_elevated_privileges(false)` is true —
  with the linger service keeping CAP_PERMITTED that is permanent), keep CAP_PERMITTED when
  shedding only EFFECTIVE caps (`f13f6247`; upstream `drop_elevated_privileges()` clears both),
  ambient-cap shed/dumpable markers (`4f731542`, `f1cae3a4`), per-session source re-verification
  (`03bbcec6`), kwin/kms source-identity routing (`fa5ab1f4`, upstream shape differs).
- **drop** — the base already contains them (upstream is the origin of KWin ScreenCast PR #5009,
  `has_/drop_elevated_privileges`, `framerateX100`, DMA-BUF EGL loading) or they only work around
  the fork's Windows-shaped core/CMake (ZakoVDD stubs, `settings_t` stubs, CMake source-list fixes,
  NVENC header includes, `cuda.cu` repairs).
- **assess** — `d9216c4d`, `f6f0cb42` (EGL DMA-BUF one-shot loading / `n_dmabuf_infos` init: the
  upstream graphics/pipewire shape differs, check whether the bug class survives),
  `35cee1de` (wrapper-path KWin permission file: KWin compares the real exe, so the env switch
  `KWIN_WAYLAND_NO_PERMISSION_CHECKS=1` remains the working path — upstream already implements it).

Also to be re-applied from the fork's *non*-commit inventory: the hook scripts and systemd/env
deployment live in the NixOS repo (`modules/home/optional/sunshine-vdisplay.nix`), not here; the
docs `docs/linux-headless-sddm-streaming.md` and `docs/vdd-prerequisite-closure.md` are portable
as-is.

this tree tracks real files under `third-party/`), then a `nix-build` of the package with
`src = /tmp/fsl-src` and a stubbed web UI; then

| Check | What it proves |
|---|---|
| compile + link (CUDA variant) | the port builds, including `cuda.cpp`/`cuda.cu` |
| `grep -ac "<marker>" <store>/bin/.sunshine-wrapped` | the change is in the artifact |
